# Лабораторная работа 14: Repository и Unit of Work

## Предметная область
**Филиалы и сотрудники** — хранение штата в файле и пакетная запись изменений.

Методичка просит один паттерн из списка. В работе показаны два связанных: репозиторий отвечает за доступ к данным, единица работы — за границы сохранения.

## Паттерн 1: Репозиторий (Repository)

### Назначение
Прячет способ хранения за интерфейсом коллекции в памяти.

### Проблема
Если окно само открывает `employees.json`, форма знает про файл, кодировку и ключи. Замена JSON на базу затронет интерфейс.

### Решение
`JsonEmployeeRepository` умеет `add`, `update`, `delete`, `get` и `get_all`. Окно вызывает эти методы и не читает файл.

## Паттерн 2: Единица работы (Unit of Work)

### Назначение
Запоминает новые, изменённые и удалённые объекты одной операции и сохраняет их вместе.

### Проблема
Каждое нажатие кнопки сразу переписывает файл. Ошибочный ввод уже на диске, отменить пачку правок нельзя.

### Решение
`UnitOfWork` копит `register_new`, `register_dirty` и `register_removed`. `commit()` один раз вызывает репозиторий. `rollback()` очищает списки, файл остаётся прежним.

### Участники
| Участник | Роль | В коде |
|---|---|---|
| Repository | Доступ к JSON | `JsonEmployeeRepository` |
| Unit of Work | Накопленные изменения | `UnitOfWork` |
| Entity | Сотрудник | `Employee` |

### Как запустить
```bash
python lab14/main.py
```

Файл `lab14/employees.json` появляется после первого commit.

### Что видно в GUI
Новые строки помечаются «новый», «изменён» или «удалить» и не попадают в файл, пока не нажата кнопка Commit. Rollback снимает пометки.

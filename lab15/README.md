# Лабораторная работа 15: Producer-Consumer

## Предметная область
**Филиалы и сотрудники** — очередь расчёта премий.

## Паттерн: Производитель-потребитель (Producer-Consumer)

### Назначение
Один поток кладёт задания в очередь, другие потоки забирают их и обрабатывают. Скорость постановки и скорость расчёта больше не связаны напрямую.

### Проблема
Если окно само считает премию каждому сотруднику, интерфейс замирает на время расчёта. Создавать новый поток на человека тоже плохо: при большой ведомости потоков станет слишком много.

### Решение
Кнопка — производитель: она только делает `queue.put(BonusTask)`. Два демона-потребителя заранее запущены и в цикле делают `queue.get()`. Готовый результат они кладут во вторую очередь, а интерфейс забирает её через `after`, не трогая виджеты из чужого потока.

Фиксированные два потока — простой пул: работники живут всё время окна и используются повторно.

### Участники
| Участник | Роль | В коде |
|---|---|---|
| Producer | Кладёт задания | кнопки в `ProducerApp` |
| Queue | Буфер | `queue.Queue` |
| Consumer | Считает премию | `WorkerPool._consume` |
| Thread pool | Повторное использование потоков | два потока в `WorkerPool` |

### Как запустить
```bash
python lab15/main.py
```

### Что видно в GUI
«Поставить 4 задания» быстро пишет четыре строки производителя. Потребители `Worker-1` и `Worker-2` разбирают очередь по одному, с паузой, и добавляют строки в таблицу. Счётчик показывает, сколько заданий ещё ждёт.

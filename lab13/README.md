# Лабораторная работа 13: Circuit Breaker

## Предметная область
**Филиалы и сотрудники** — запрос фонда оплаты у удалённого HR-сервиса.

## Паттерн: Предохранитель (Circuit Breaker)

### Назначение
Останавливает повторные вызовы сервиса, который уже не отвечает, и через паузу проверяет, не ожил ли он.

### Проблема
Если HR-сервис упал, каждое нажатие «посчитать фонд» ждёт ошибку сети. Клиент филиала продолжает долбить недоступный адрес и сам захлёбывается ошибками.

### Решение
`CircuitBreaker` оборачивает `RemoteHRService` и держит три состояния:

- **CLOSED** — вызовы проходят. После 3 ошибок подряд цепь становится OPEN.
- **OPEN** — вызов не уходит в сервис, сразу возвращается отказ. Через 8 секунд цепь становится HALF-OPEN.
- **HALF-OPEN** — пропускается пробный вызов. Успех закрывает цепь, ошибка снова открывает её.

### Участники
| Участник | Роль | В коде |
|---|---|---|
| Service | Удалённый расчёт | `RemoteHRService` |
| Circuit Breaker | Учёт сбоев и состояния | `CircuitBreaker` |
| Client | Филиал | `BreakerApp` |

### Как запустить
```bash
python lab13/main.py
```

### Что видно в GUI
Галочка «HR-сервис недоступен» имитирует сбой. Три запроса подряд красят состояние в OPEN, следующие клики отклоняются без обращения к сервису. Если снять галочку и подождать 8 секунд, следующий запрос идёт как пробный и возвращает цепь в CLOSED.
